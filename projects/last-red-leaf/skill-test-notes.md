# Paper Collage Skill 峰值测试记录

本文件记录《最后一片红叶》制作过程中发现的 Skill 问题与优化点。测试结束后统一讨论和实现；制作过程中只追加证据，不提前修改 Skill 行为。

## OPT-001：概念确认卡片应显式列出有界枚举参数

- 发现阶段：`capability-review` 的概念、预算与 provider 合并确认。
- 当前表现：卡片只询问“是否按当前故事、时长、画面方向、预算和服务方案继续？”，修改路径是一个笼统的“修改后再继续”自由文本入口。
- 用户问题：制作档位属于固定枚举，而且直接改变生图预算、分层深度、姿态数量、制作时间和成本；如果卡片不列出选项及数字，用户在确认前无法知道有哪些档位、各自是什么意思或如何选择。
- 期望行为：把 `draft`、`balanced`、`full-depth` 作为卡片中的直接可选项；针对当前幕数显示精确的生图尝试上限，并用一句话说明对最终成片的影响。
- 当前两幕示例：`draft` 最多 5 次，画面较扁平且大量复用；`balanced` 最多 6 次，关键场景有适量独立分层；`full-depth` 最多 9 次，最大化环境视差与角色姿态变化。
- 泛化原则：凡是固定枚举且会明显改变数字预算、输出范围或成本的参数，都应优先使用结构化选项，不应只藏在“其他/修改”自由文本中。
- 状态：已记录，延后到本次成片测试结束后统一评审与实现。

## OPT-002：`project:assets-ready` 在 preview 阶段应支持幂等复核或提前失败

- 发现阶段：首轮预览因响度失败后，修改 `audio.narration.volume` 并重新执行就绪检查。
- 当前表现：命令先成功完成旁白同步、推断时长、字幕、v4 验证和 30/30 质量复核，最后才由 `project:advance` 报错“动作 assets-ready 不能在 preview 阶段执行”。
- 用户问题：输出看起来先全面成功再整体失败；在预览修订循环里，用户和 Agent 难以判断就绪复核是否有效、是否还需要补做步骤。
- 期望行为（二选一）：
  1. preview / human-review 阶段允许 `assets-ready` 作为幂等复核，只刷新同步与验证结果，不重复 advance；或
  2. 在执行任何写入和长检查前先识别阶段，快速返回“当前已在 preview，请直接运行 project:preview；如需完整复核请用某个明确命令”。
- 证据：响度修正后的 `project:validate` 为 0 错误 0 警告、`project:quality prepare` 为 30/30，但重复 `project:assets-ready` 仍以 exit 1 结束。
- 状态：已记录，等待测试结束后评审。

## OPT-003：在整段视频渲染前增加响度预检与音频-only 快速修订路径

- 发现阶段：第一次 784 帧预览完成后的最终报告。
- 当前表现：首轮画面、连续性、时长和真峰值全部通过，但综合响度为 -21.36 LUFS，低于 -16 ± 3 LUFS；将旁白总线从 1.0 调到 1.85 后，系统重新渲染全部 784 帧，第二轮得到 -16.01 LUFS。
- 用户问题：这是只影响音频混合的参数，但当前要重复完整浏览器逐帧渲染；full-depth 项目越长，等待成本越高。
- 期望行为：
  - 在 `assets-ready` 或 preview 前先根据旁白源文件、SFX 与配置做一次响度预检，给出推荐 gain；
  - 当视频画面指纹未变、仅音频总线变化时，复用无声视频流并重新混音/封装，再执行最终报告；
  - 仍由最终成片报告作为权威，不用预估替代真实验证。
- 证据：首轮 -21.36 LUFS / -8.71 dBTP；音量系数 1.85 后为 -16.01 LUFS / -3.15 dBTP，视觉质量指纹始终保持 30/30。
- 状态：已记录，等待测试结束后评审。

## OPT-004：故事板节拍与 cue 证明点应在生产前形成可满足合同

- 发现阶段：`project:quality prepare` 的 composite gate。
- 当前表现：第二幕故事板有 5 个节拍，但批准的 proofTimes 只有 3 个；`s2-b1-leaf-lifts` 需要音效和可视动作，却没有自己的证明点。cue 不绑定 proof 会被质量门判为 needs-revision，而在 project.json 单独新增 cue proof 又会被验证器以“项目证明时刻必须与已批准故事板完全一致”拒绝。
- 本次绕行：把“掀叶”cue 延长到已有的“落叶成舟”证明点并绑定它，虽然合同可通过，但事件级证据不够精确。
- 期望行为：
  - 概念/故事板锁定前检查每个需要证明的节拍是否有 proofTime；
  - 或允许在不改变已批准叙事内容的前提下追加 cue-specific proof，并记录为证据增强而非概念变更；
  - 质量准备应在昂贵素材与整片渲染前报告这种不可满足合同。
- 状态：已记录，等待测试结束后评审。
